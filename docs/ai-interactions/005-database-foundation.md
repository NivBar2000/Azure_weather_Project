## Objective

Add a production-oriented PostgreSQL and TypeORM foundation, an initial reversible schema migration, and a local PostgreSQL-only Compose service without implementing authentication or forecast persistence APIs.

## Relevant decisions

- Use separate validated database environment variables instead of a full connection string so secrets are not embedded in logs or documentation.
- Use one shared TypeORM options factory for NestJS startup and the TypeORM migration CLI, with schema synchronization permanently disabled.
- Store timestamps as PostgreSQL `timestamptz`, use relational columns for searchable forecast fields, and reserve JSONB for the complete forecast snapshot.
- Protect saved history with insert-oriented entities and a restrictive user foreign key; no update or persistence endpoints are introduced.
- Keep HTTP tests independent of an external database by composing only the modules under test, while focused configuration and entity-metadata tests protect the database foundation.
- Use a PostgreSQL 17.6 Alpine image for the temporary PostgreSQL-only local Compose topology.
